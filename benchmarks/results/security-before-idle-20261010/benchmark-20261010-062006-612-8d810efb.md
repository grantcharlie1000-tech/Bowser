PID plus process-creation time detects reuse; parent edges exclude children older than the current parent. Hard-fault and page-in metrics are unavailable. One-second CPU sampling can miss short-lived children.

`blank-idle` samples about:blank memory after 2 seconds and idle CPU/RAM over the configured window, without submission. `blank-submit` measures launch, focused input readiness, verified phrase entry, and Enter; `submitted_ms` is captured immediately after Enter key-up, with no later sampling or provider response wait. Its page, idle, and memory metrics are n/a by design. `light` and `demanding` launch their local fixture directly; the title marker is polled immediately after visible/responsive, without an address-focus step before readiness. Their input-ready and submitted metrics are n/a. Harness UI timings use Stopwatch/QPC for all browsers; Bowser app event logs are retained as diagnostics. Missing values remain blank in CSV and appear as `n/a` here.

Battery use is unmeasured. Runtime disk size counts versioned Evergreen WebView2 application directories only and is separate from Bowser files and user profiles. Bowser app disk size counts the release executable and an adjacent `WebView2Loader.dll`, if present.

Disposable profiles are scheduled for removal after summary generation; every process group confirmed shutdown and profile state remained known.

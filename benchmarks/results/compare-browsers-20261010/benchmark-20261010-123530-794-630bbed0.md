# Bowser benchmark results

Captured: 2026-10-10 12:45:55 +01:00; CSV: `benchmark-20261010-123530-794-630bbed0.csv`; metadata: `benchmark-20261010-123530-794-630bbed0.json`.

`cold-profile` uses a new isolated browser profile. `warm-profile` restarts the process with the same profile from its paired cold run. Windows standby/file cache was not flushed; OS cache state is uncontrolled. No browser security features were disabled. Each reported process metric sums the launched browser and its descendants; CPU is normalized by logical processor count.
Unrelated applications are excluded from each process-group total, while their background CPU, memory pressure, and disk activity remain uncontrolled host noise.
Process-group snapshots are approximate. Native `GetProcessMemoryInfo(PROCESS_MEMORY_COUNTERS_EX)` provides per-PID working set and private usage where access permits; the same inventory records `Win32_Process.PageFileUsage` separately as `wmi_pagefileusage_proxy`. Private totals identify their source and use the proxy only when native coverage is incomplete. PID plus process-creation time detects reuse; parent edges exclude children older than the current parent. Hard-fault and page-in metrics are unavailable. One-second CPU sampling can miss short-lived children.
Raw CSV includes native and WMI proxy values, their source labels, process counts, creation-time identity, role/command-line type where identifiable, sample time, and coverage errors for each RAM snapshot.
Browser launch order rotates across workload, run, and condition to reduce systematic cache-order bias. Page title markers are polled every 10 ms and the recorded outer stopwatch timestamp is the first responsive observation.

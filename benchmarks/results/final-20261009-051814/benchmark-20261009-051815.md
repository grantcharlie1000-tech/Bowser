`cold-profile` uses a new isolated browser profile. `warm-profile` restarts the process with the same profile from its paired cold run. Windows standby/file cache was not flushed; OS cache state is uncontrolled. No browser security features were disabled. Each reported process metric sums the launched browser and its descendants; CPU is normalized by logical processor count.
Unrelated applications are excluded from each process-group total, while their background CPU, memory pressure, and disk activity remain uncontrolled host noise.
RAM and CPU use one Win32_Process inventory per process-group snapshot: WorkingSetSize bytes, PageFileUsage KiB for private/commit bytes, and cumulative user/kernel CPU in 100 ns units. CreationDate distinguishes reused PIDs and validates parent edges. This is an approximate near-snapshot; one-second CPU sampling can miss children that start and exit between samples. A missing root or unreadable live process counter fails the sample rather than recording zero.
Raw CSV includes idle/page process counts and JSON per-process PID/creation-time/name/working-set/private-bytes/CPU details for each RAM snapshot.
Browser launch order rotates across workload, run, and condition to reduce systematic cache-order bias. Page title markers are polled every 10 ms and the recorded outer stopwatch timestamp is the first responsive observation.

Its page, idle, and memory metrics are n/a by design. `light` and `demanding` launch their local fixture directly; the title marker is polled immediately after visible/responsive, without an address-focus step before readiness. Their input-ready and submitted metrics are n/a. Harness UI timings use Stopwatch/QPC for all browsers; Bowser app event logs are retained as diagnostics. Missing values remain blank in CSV and appear as `n/a` here.

Battery use is unmeasured. Runtime disk size counts versioned Evergreen WebView2 application directories only and is separate from Bowser files and user profiles. Bowser app disk size counts the release executable and an adjacent `WebView2Loader.dll`, if present.

Disposable browser profiles are scheduled for removal after summary generation; every process group confirmed shutdown.

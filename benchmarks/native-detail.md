# Native attribution pilot

`--diagnostic-detail` requires `--diagnostic-log` and the same explicit isolated `--data-dir` protections. It does not enable benchmark behavior or disable production security/privacy. It is off for ordinary use and primary performance arms.

The short pilot alternates three arms on the same runner: immutable frozen diagnostic baseline, current candidate with detail off, and the identical current candidate with detail on. Three matched pairs per fresh/reused profile are exploratory attribution and overhead controls, not accepted gain estimates. Untouched-main versus current-candidate diagnostic off, and current-candidate standard logging off/on controls are rerun as well. No overhead subtraction is permitted. Separate cheap timing and resource sampling arms remain unchanged.

CSV adds `view,pid,private_bytes,count` after the existing navigation columns. Configure spans, actual blocked-pattern/JSON preparation spans and numeric payload sizes, and successful filter registration counts carry the content tab ID. Fixed chrome lifecycle events use fixed view labels and host IDs in `count` (request/result events precede allocation and have ID zero). Snapshot events use a unique snapshot ID in `count`. PID ownership is observed asynchronously through native frame source information, matched only against exact embedded chrome URLs. Arbitrary URLs, page titles, frame sources and command lines are not recorded.

`renderer_private_inventory` records each renderer PID's native PrivateUsage once per snapshot. `chrome_renderer_private` maps fixed chrome views to those PIDs; several views may share a renderer. Deduplicate by PID within one completed snapshot. Do not add per-view bytes, do not call private commit working set or PSS, and do not infer that an unmapped renderer is necessarily a content tab. Failed/unsupported/incomplete snapshots or unavailable private counters are ineligible. This asynchronous attribution is not the settled resource endpoint and is not a continuous peak.

`native-detail-analyze.py` retains per-sample configure distributions, successful registration counts, lifecycle rows, snapshot coverage and deduplicated attribution. Raw rows and failed samples remain in the standard artifact. The regular analyzer also reports the paired detail-on/off controls, but fewer than ten pairs does not satisfy primary acceptance.

Lifecycle close-request and COM close-result events are separate; COM success does not prove helper-process exit or released memory. The harness separately confirms owned/profile process-tree drain. Snapshot labels establish frame association, not exclusive ownership or per-view memory. PID creation identity is retained by the separate owned resource inventory, not by these asynchronous attribution rows. Cross-check a stable owned inventory before selecting a retained-memory optimization target. Request/result host IDs of zero are not a general concurrent duplicate-host lifetime identifier.

The attribution pilot's primary timing/resource/controls use explicit startup-only mode: no omnibox submission, suggestion opening, extra navigation or accessibility activation. Input latency is null with an exclusion reason, never passed or zero. Idle RAM, CPU, process count, disk and reused-profile state are a different workload from the earlier post-Enter matrix; decreases across that boundary are not optimization gains. Frozen baseline and candidate rerun with the identical startup-only harness. StartupOnly plus tab-flow is rejected. The independent mandatory interaction lane also skips the legacy probe, then performs a single exact-focus/value semantically verified URL submission before popup/Settings, requiring unique acknowledgement, owned title and its own successful native token/navigation segment after log flush. No typing retry or hidden rescue is performed. Its UIA-conditioned input proxy is exploratory, not a primary matched input-latency claim.

## Policy-preserving registration experiment

The next candidate removes an existing registration glob only when a permanently retained original glob provably covers it. The conservative token-alignment proof recognizes documented ASCII wildcard syntax; unknown syntax, excessive length or exhausted bounded proof work retains the original filters. The original filter-cap wildcard fallback occurs before minimization. Native resource contexts, worker source kinds, API branches, handler behavior and installation ordering are unchanged. Unit tests check retained witnesses, equivalent cycles, syntax refusal, budget fallback and an independently matched exhaustive small corpus.

The immediate pre-optimization reference is immutable source `46ee3b3ef98a4c7603967d22df9cb1490ca936c1`, EXE SHA256 `22674e9fdaa589915200b3058765ec202843d87d7ecabdad081911537004bd2b`, 7,817,216 bytes, from verified artifact 12125524797. The workflow builds the actual optimized candidate with the same release features/toolchain. Primary timing and resource lanes use ten alternating matched baseline/candidate pairs for each fresh/reused profile, detail off, identical startup-only workload and successful navigation/HTML activation/drain gates. A separate two-pair detail arm checks actual registration counts and cost; it is not a gain-acceptance matrix.

Mandatory native dispatch parity uses ordinary loopback navigation and 23 checks across fetch, XHR, scripts, images and dedicated/shared/service workers, with matching and nonmatching URLs. Unique token receipts, owned title and native navigation success are required; failures remain raw evidence. The independent early semantic-input and first/warm popup/Settings smoke remains mandatory. Registration reductions are not accepted speed or memory gains until native correctness and matched metrics pass; private commit, CPU intervals, disk and EXE size are reported independently.

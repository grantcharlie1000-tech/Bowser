# Interaction ordering control (not a performance acceptance matrix)

`--diagnostic-interaction` requires the existing explicit diagnostic log and isolated data-root safeguards. It does not select benchmark/dev behavior, query process/frame inventory, change filter policy, add a network endpoint, or relax CSP/Trusted Types. It is off in ordinary and frozen primary measurements.

The embedded toolbar observer is inert until the opted-in native host enables it. It passively observes Enter capture/bubble and address focus/blur; it never changes a value, selection, focus, propagation or default action. The native host applies the existing exact top-level origin checks. A strict toolbar-only diagnostic grammar accepts five fixed event names and an unsigned16-bit mask, at most128 wire bytes, with a separate32-message burst/32-per-second cap. It never spends product action tokens or reaches action dispatch. Unknown/malformed messages retain the normal action quota and parser path. Ordinary OFF mode retains quota-before-string-read order.

DOM mask bits0–11: event composing, Ctrl, Shift, Alt, Meta, active address input, document focused, default prevented, exact fixed Settings address, whole value selected, empty value, keyCode229. Bits12–15: toolbar composing, pending edit, suggestion selection nonzero, suggestion sequence current. No arbitrary URL, input text, page title or frame source is recorded. Native Enter logs its actual fixed chrome view, key state/modifiers, and the original accelerator handler's single handled result. Fixed-label logs trace bridge submit/focus/suggestion dispatch, internal-page routing/open plan/refusal and page focus/show requests.

DOM telemetry QPC marks native receipt, not DOM execution time. Cross-process causality cannot be inferred from receipt order alone. Any product/diagnostic quota drop, parser drop, unavailable arming evidence or App borrow-coverage drop makes observation incomplete. Missing records then cannot establish missing Enter or missing native dispatch. A single buffered-log checkpoint publishes observer arming; the harness waits at most five seconds before instrumented input, outside performance claims. Further events remain buffered until shutdown.

For this control, candidate and reference are both rebuilt with identical generated UI/native instrumentation and toolchain/features. The reference tree restores only src/blocker.rs and removes src/blocker/registration.rs; CI asserts those are the only differences and records its exact build-tree and patch hashes. It is explicitly NOT the original46ee executable. Original primary artifacts/hashes and all failed attempts remain immutable. Fixed alternating flag-OFF/ON attempts on both binaries quantify observer effects descriptively; they do not replace the frozen ten-pair startup/resource comparison or establish typing latency.

Interaction controls use newly created disposable production data roots with ordinary auto-update.txt=false, reject pending/trial/staged updater state, and hash every input against a fixed source manifest before each launch and after cleanup, including failed rows. No restore-and-continue is allowed. Ownership coverage and process-tree drain are required before later attempts/lanes; any unresolved identity or cleanup writes a shared fail-closed marker. A ValuePattern lane bypasses keystrokes but may still dispatch DOM input/change and autocomplete, so its failures are investigated rather than dismissed as unsupported. The earlier burst-key and updater-contaminated failures remain preserved separately.
